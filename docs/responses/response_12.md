# 질문 12 — SSH·DB 포트 전체 공개의 위험과 대안

## 질문

SSH(22) 또는 DB 포트를 `0.0.0.0/0`으로 열면 안 되는 이유와 대안은 무엇인가?

## 답변

`0.0.0.0/0`은 인터넷의 모든 IPv4 주소를 의미한다. SSH 22를 전체 공개하면 자동화된
포트 스캔, 계정 이름 추측, 자격 증명 대입, 취약점 공격에 지속해서 노출된다. Private Key를
사용하더라도 불필요한 공격 표면과 로그·CPU 부하가 생기며, 키가 유출됐을 때 즉시 침해로
이어질 수 있다.

DB 포트는 더 위험하다. DB 인증 화면이 인터넷에 직접 노출되고, 약한 비밀번호·미패치
취약점·설정 오류가 데이터 유출이나 삭제로 연결될 수 있다. 애플리케이션 서버만 DB에
접근하면 되는 구조에서 인터넷 전체 공개는 필요하지 않다.

대안은 다음과 같다.

- SSH: 학습자의 고정 Public IPv4 `/32`만 허용
- 운영 SSH: AWS Systems Manager Session Manager 또는 VPN/Bastion 사용
- DB: Private Subnet에 배치하고 EC2 애플리케이션 Security Group만 소스로 허용
- 임시 작업: 필요한 시간에만 규칙을 추가하고 작업 후 즉시 제거
- 공통: 키 회전, MFA, 로그 모니터링과 정기 패치 적용

이번 실습에서는 SSH를 학습자 IP `/32`로 제한하고 DB 포트는 전혀 열지 않았다.
