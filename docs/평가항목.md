# 평가 항목

클라우드 인프라 & 웹 서비스 배포 미션의 평가 기준입니다.  
**구현 검증 → 설계 설명 → 개념 이해 → 운영·확장** 순으로 난이도가 올라갑니다.

---

## 항목 1 · 구현·구성 검증

> 제출물과 실제 환경이 요구사항을 충족하는지 확인합니다.

### 네트워크 & 컴퓨팅

- VPC, Public Subnet, Internet Gateway, Route Table(`0.0.0.0/0` → IGW)이 구성되어 있는가?
- EC2에 SSH로 접속 가능하며, 웹 서버가 실행 중인가?

### 보안 & 접속 검증

- 보안 그룹 인바운드가 **필요 포트만** 허용하며, SSH(22)가 특정 IP로 제한되어 있는가?
- 외부 접속이 아래 방식 중 **1개**로 검증되는가? *(제출자가 선택한 방식으로 확인)*
  - **(A)** 브라우저 `http://<퍼블릭IP>` 접속 시 페이지 정상 로딩
  - **(B)** `GET /health` 호출 시 200 및 고정 응답 확인

### 리소스 정리

- 리소스 정리 체크리스트에서 최소 **5종**(`EC2` / `EBS` / `EIP` / `IGW` / `VPC`) 정리 완료를 확인할 수 있는가?

## 항목 2 · 설계·구성 설명

> 본인이 구성한 아키텍처와 선택 근거를 설명할 수 있는지 확인합니다.

### 네트워크 흐름

- `외부 → IGW → Subnet → EC2`로 이어지는 네트워크 흐름을 **다이어그램 기준**으로 설명할 수 있는가?

### 보안 설계

- 보안 그룹 규칙을 어떤 기준으로 최소화했는지 *(허용/미허용 포트)* 설명할 수 있는가?

### 접속 검증 방식

- 외부 접속 검증을 **(A)** 또는 **(B)** 중 무엇으로 선택했고, 그 선택을 위해 무엇을 어떻게 구성했는지 설명할 수 있는가?

### 리소스 관리

- 실습 리소스를 추적/정리하기 위해 어떤 기준 *(태그, 이름 규칙, 체크리스트)* 을 사용했는지 설명할 수 있는가?

---

## 항목 3 · 핵심 개념 이해

> 왜 그렇게 구성했는지, 원칙과 트레이드오프를 이해하고 있는지 확인합니다.

### 라우팅

- Public Subnet Route Table의 기본 경로(`0.0.0.0/0` → IGW)가 **필요한 이유**를 설명할 수 있는가?

### 보안 원칙

- Security Group과 IAM의 **책임 범위 차이**를 설명하고, *최소 권한*이 왜 필요한지 설명할 수 있는가?
- SSH(22) 또는 DB 포트를 `0.0.0.0/0`으로 열면 안 되는 **이유와 대안**을 설명할 수 있는가?

### 트러블슈팅 방법론

- 트러블슈팅에서 **`가설 → 검증`** 순서를 유지한 이유와, 로그/근거를 어떻게 활용했는지 설명할 수 있는가?

---

## 항목 4 · 운영·확장·비용

> 장애 대응, 권한 문제, 스케일링, 비용 관리 역량을 확인합니다.

### 장애 진단 순서

- 외부 접속이 안 될 때, 어떤 순서로 점검하는지 설명할 수 있는가?

  `라우팅 → SG → 퍼블릭 IP/DNS → 서버 프로세스/로그`

### IAM 최소 권한

- IAM 권한이 부족해 작업이 실패했다면, **권한을 무작정 올리지 않고** 어떤 방식으로 필요한 최소 범위를 찾아갈지 설명할 수 있는가?

### 스케일링

- 트래픽이 늘어 인스턴스를 2대로 늘려야 한다면, 현재 구조에서 **무엇이 병목**이며 어떤 구성요소 *(ALB 등)* 를 추가할지 설명할 수 있는가?

### 비용 관리

- Billing에 예상치 못한 비용이 찍혔다면, **어떤 리소스부터 의심**하고 어떻게 추적/정리할지 설명할 수 있는가?
